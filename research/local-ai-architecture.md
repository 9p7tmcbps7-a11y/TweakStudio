# Local AI and GitHub architecture notes

Research checked 2026-10-21.

- `llama.cpp` is a C/C++ inference engine with an iOS XCFramework; its upstream server exposes OpenAI-compatible chat-completions and function/tool calling, with tool use generally enabled via Jinja templates (`--jinja`). A TweakStudio integration could either link the library and import GGUF model files, or call a local OpenAI-compatible server endpoint. Source: https://github.com/ggml-org/llama.cpp ; iOS XCFramework: https://github.com/ggml-org/llama.cpp/blob/master/docs/xcframework.md ; server: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md
- Apple documented MLX Swift/C APIs across iOS platforms in WWDC25. That demonstrates an on-device iOS path, but it is a different integration/build architecture from the current Objective-C Theos bundle. Source: https://developer.apple.com/videos/play/wwdc2025/315/ ; MLX repo: https://github.com/ml-explore/mlx
- ATS normally requires HTTPS for URLSession. Apple provides targeted local-network and domain exception keys, and cautions that broad exceptions weaken security. A configurable local endpoint should avoid globally disabling ATS where possible. Source: https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity
- GitHub OAuth Device Flow requires a registered OAuth app's client ID and Device Flow enabled. It uses a user code and verification page, then polls at the returned interval; the user code expires after 15 minutes. The client ID is public app configuration, while authorization yields an access token. Source: https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps ; app setup: https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app

Architecture decision needed before implementation: directly embed llama.cpp and load imported GGUF files; connect to a user-selected local OpenAI-compatible server; or support both. The first is more self-contained but adds native runtime complexity and memory/storage cost. The server connection is smaller and can support multiple local runners, but requires the user to start a compatible service. Small models may vary in tool-call formatting, so agent tools should be validated/allowlisted by the app rather than letting model text directly execute arbitrary shell commands.
